# 动作分级表 v1（制度文件 · A1）

> **定位**：先于代码的制度层。白名单机制（`ActionExecutor.whitelisted()`）是这张表的执行器，
> 这张表是白名单的立法依据。模型自报的 `risk` 只是参考信号，**分级以本表为准**。
> 来源：`docs/v2-phase-plan.md` D1.2（预注册决策 #1：分级用制度文档，不用代码 schema）。
> 版本：v1（2026-10-31）· 改表需留痕（见文末变更纪律）。

## 1. 分级三元组与闸门

每个动作类标注三个维度：

| 维度 | 取值 | 说明 |
| --- | --- | --- |
| **可逆性** | 可逆 / 难逆 / 不可逆 | 撤销该动作的成本：一条命令能撤回 = 可逆；需要专门流程 = 难逆；撤不回 = 不可逆 |
| **影响面** | 单实例 / 跨实例 / 跨系统 | 动作波及范围 |
| **爆炸半径** | 一句话回滚成本 | 出错时最坏损失 |

三个维度合成一个**闸门**档位：

| 闸门 | 语义 | 谁决定 |
| --- | --- | --- |
| `auto` | 自动执行，事后审计留痕（approvals.jsonl） | 白名单 + risk=low 策略 |
| `approve` | 必须人工批准，批准即执行并回显 | 人（审批闸门 REST） |
| `forbidden` | 永不执行，提取到也只记录 | **制度线，不随模型能力移动** |

## 2. 首版分级表

锚定现状：白名单内实际存在的动作只有一类——解除 chaos-demo 故障注入
（`chaos:off:<scene>`，5 个场景硬编码在 `ActionExecutor`）；白名单外
`executable_command=null`，进 pending 队列「批准也仅记录」。

| 动作类 | 可逆性 | 影响面 | 爆炸半径 | 当前闸门 | 毕业条件 |
| --- | --- | --- | --- | --- | --- |
| `chaos:off:*`（解除故障注入） | 可逆（可重新 `on`） | 单实例（chaos-demo） | 近零：注入本就是人为制造 | **auto** | 已毕业——本表的基准点 |
| `chaos:on:*`（注入故障） | 可逆 | 单实例（chaos-demo） | 近零 | approve | 不设毕业——靶场操作，人工控制注入节奏 |
| 服务/进程重启类（未来） | 难逆（会话/状态丢失） | 单实例 | 中：恢复窗口内业务受损 | approve | 信任标定实验（A2）≥3 代际 0 事故 + 副作用清单成文 |
| 数据写入/删除类（未来） | **不可逆** | 跨实例 | 不可回滚 | **forbidden** | **无——制度线，永不毕业** |

最后一条是本表的存在理由：`forbidden` 不是模型能力的函数。模型再可靠，
不可逆动作的授权也留在模型外面——这是 V2 的锚（自我授权悖论）。

## 3. 与提取器/审批流的耦合规则

1. **冲突裁决**：提取器输出 `{description, risk, executable_command}`，
   `risk` 是模型自报信号。本表闸门与 `risk` 冲突时，**以本表为准**取更严档位。
   例：模型报 `risk=low` 的动作若落入 approve 类，仍进人工队列。
2. **闸门在白名单之前**：自动执行条件维持 `whitelisted(cmd) && risk=="low"`，
   但白名单内容必须能回溯到本表某一行。白名单扩容 = 本表先改，代码后跟。
3. **误拦判定基准**：信任标定实验（A2）的「制度误拦」分类，以本表闸门列为
   基准——正确动作被本表挡下不算误拦（制度边界起作用），被模型自报 risk
   或白名单遗漏挡下才算。
4. **审计可回溯**：每次 `auto` 执行带 `decidedBy="auto-policy:whitelisted-low-risk"`
   落 approvals.jsonl（现状纪律，不变）。

## 4. 现状与缺口（诚实条款）

- **提取器无兜底**：只走 primary 模型，主模型故障时全场提取失败（D12 盲测
  6 场全灭，挂账 known-defects）。关账方案见 v2-phase-plan 期 2 D2.1 前置项。
- **沙箱未落地**：DESIGN.md D11 计划的 sandbox-verifier 未实现；现状是
  「审批后真实执行 + HTTP 回显入审批记录」。当前动作面限于 chaos:off 靶场
  内部调用，风险可接受；扩类前必须先补沙箱。
- **预留档位无代码**：重启类/数据类两行是制度预留，提取器 schema 尚无
  reversibility/blast_radius 字段（与兜底关账合并改造，一次动刀）。

## 5. 变更纪律

- 本表是**制度文件**：改表 = 制度变更，须 git commit 留痕 + 周日复盘记录一条
- `forbidden` 行**不可通过常规流程修改**；若确需变更，等价于重新立法，
  必须单独成文论证并另立版本（v1 → v2），不接受在原表上原地改档
- 毕业依据只有实验数据（A2 三分类表），不接受「模型感觉更可靠了」类论证
