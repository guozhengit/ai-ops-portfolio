## 结论

- **根因**：应用侧 HikariCP 连接池被混沌实验 `pool-exhaustion` 注入而持续钉死，在用连接 **10/10（100%）**，自 **16:57:51 CST** 起持续未恢复。这是**连接借走不归还的持续耗尽型**故障，**不是流量突增、也不是数据库侧容量问题**。
- **瓶颈定位**：耗尽发生在**应用连接池**，不在 MySQL 服务端。DB 侧 `threads_connected=6/150（4%）`、QPS≈46、慢查询=0、行锁等待=0、`max_connections` 拒绝=0，服务端完全健康。因此**严禁对 DB 做扩容 / KILL 会话 / 杀连接类处置**——无会话可杀且会误伤。
- **影响面**：池满 → 获取连接超时 → 探针失败被摘，已造成 **18 个 zkt-services 实例 `up=0` 全灭、Nacos 仅剩 1 个注册实例**，约等于全站不可用（P1 与实际影响相符）。
- **触发源**：唯一活跃故障为混沌注入 `pool-exhaustion`（on=1、全程无 off）；slow-sql / memory-leak / disk-full / nacos-flap 均关闭且指标为 0；无发布、流量、批处理旁证。
- **首要动作**：停止混沌注入（off）并滚动重启被钉死的应用实例即可快速恢复；因注入未关，单纯重启可能被再次钉死，**必须先关注入**。
