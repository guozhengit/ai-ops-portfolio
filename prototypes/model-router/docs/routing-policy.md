# 路由策略（model-router）

这份文档回答一个问题：**一个请求进来，它到底是怎么被决定发到哪去的，以及中途出错时怎么退。**
所有规则都能在代码里对到具体方法，数字都有实测出处（见 `channel-verification-miku-20261029.md`）。

---

## 1. 渠道是什么

渠道 ≠ 供应商。渠道是 **base-url + key + 模型清单 + 价目** 四元组。

这个定义是被实测逼出来的：同一个 `https://mikuapi.org/v1`，两把 key 的可用模型**完全不相交**
（新 key 只通 `deepseek-v4.1-flash`，gpt-5.x 全 404；旧 key 反过来）。所以配置里同一个 base-url
出现了两个渠道：`miku`（新 key，主档）和 `miku-gpt`（旧 key，priority 9，留作 503 故障样本）。

缺 key（环境变量没设）的渠道在装配期直接禁用并告警——半配置的渠道比没有渠道更危险。

## 2. 选路顺序

```
请求 model
  → 渠道直供该模型？            → 用原名
  → 否则查别名表「渠道id:上游模型」 → 用上游模型名（请求体 model 字段被改写）
  → 都不匹配                    → 该渠道不进入候选
候选排序：priority 升序 → 同级按输出单价升序（单价未知的排最后）
```

- 别名是降级链：`gpt-5.4-mini → [miku-gpt:gpt-5.4-mini, ark:doubao-seed-2.1-turbo, mimo:mimo-v2.6-flash]`。
  请求方只认一个名字，路由负责把它换成该渠道真能吃的模型名。
- 排序把「价目未知」排在同优先级最后：没价目的渠道不该优先花钱。
- 响应头 `X-Router-Channel` 告诉你这一发最终走了谁。

### 显式锁渠道（策略让人来拍板）

调试、灰度、以及「同一个请求换供应商比效果」时，自动选路必须能让位：

- 请求头 `X-Router-Pin: ark`
- 或模型名写成 `<渠道id>:<模型名>`，例如 `ark:doubao-seed-2.1-turbo`

前缀只是寻址语法，不是模型名的一部分——账本里记的是剥离后的名字。
锁了就锁了：**即使该渠道正在冷却也照发一次**，否则「我就是要打它」这个诉求没法表达；
真失败就如实返回失败。锁到不存在的渠道返回 400 `unknown channel`。

## 3. 失败语义（这是全套设计里最容易做错的地方）

| 状态码 | 定性 | 处置 |
| --- | --- | --- |
| 500 / 502 / 503 | 瞬态 | 换下一个渠道 **并计入熔断** |
| 429 / 408 / 超时 / 连接失败 | 瞬态 | 同上 |
| 404 `model_not_found` | 确定性 | 只换渠道，**不熔断** |
| 400 / 401 / 402（余额） | 确定性 | 只换渠道，**不熔断** |

理由：熔断是为了躲开「现在不健康」的渠道；而 404/402 说的是「这个配置根本不成立」，
熔不熔断它都是坏的，计数只会白白增加延迟。这条已固化成 `HttpChannelStatusTest`——
用本地 HttpServer 打真实状态码断言，不是靠 mock 猜语义。

熔断：连续失败 `failure-threshold` 次（默认 2）开闸，`cooldown`（默认 60s）后放行一次半开探测。

## 4. 启动期能力探测

`router.probe-models`（默认开）：起来时对每个渠道打一次 `GET /v1/models`，
拿实际权益校准配置里声明的模型清单。

- **部分不符**：摘掉不符的那几个（声明里写了但 key 没买的模型，请求期必然 404）
- **全部不符**：保守保留声明并报错日志。这种情况更像 `/models` 口径不一致而不是配置写错
  ——实测 ark 的 `/api/plan/v3/models` 探测不通，正是这条规则没让它被误杀
- **探测无结论**（非 200 / 超时 / 格式不认识）：保留声明清单。探测失败只说明这条探测路径不通，
  不说明渠道不可用

别名链里指向已被摘除模型的条目会一并删掉，否则降级会跳向一个注定 404 的上游。

## 5. 成本账

每次成功调用往 `data/usage.jsonl` 追加一行：
`ts / channel / model / upstreamModel / promptTokens / completionTokens / costUsd / costKnown / prices / latencyMs / stream`。

纪律：**价目未知就记 `costUsd: null` + `costKnown: false`，绝不记 0**。
第三方中转常常没有公开价目，记 0 等于把「不知道」写成「免费」，比不记更糟。

流式没有响应头可用，token 只在最后一个 SSE 帧里。`SseUsageStream` 做旁路抄表——
字节原样透传，顺手把 usage 抄下来，**传完再落账**。实测一条 263 帧的流式调用记下了
`promptTokens=35, completionTokens=262`，成本仍然是 `null`：token 精确了不代表价目就变已知了。

## 6. 观测入口

- `GET /v1/models`：全站唯一清单，三路合并（TTS 引擎 / LLM 渠道 / 别名）。
  每条带 `kind`（tts / llm / alias，可能组合）、`owners`、`available`。
  **别名必须在清单里**——请求方是照着这张表挑名字的，挑不到他就会绕过路由直连上游。
- `GET /ui/api/status`：`channels` 数组给出每个渠道的 priority、模型、是否在冷却、价目是否已知。
