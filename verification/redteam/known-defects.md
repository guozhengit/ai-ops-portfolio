## 我们的验证不证明什么

每个验证产物先声明边界，再谈结论。首批四条，后续随真机核对补充：

1. **precision/recall = 1.000 只覆盖 drift 维度**。黄金答案（`prototypes/infra-checkup/scoring/groundtruth-160.json` 的 `_scope_note` 已声明）只含 drift；credscan 靠 fixtures 保证、exposure 本轮 0 结论，均不在该数字覆盖范围内
2. **e2e / 盲测数字来自「现场跑完即停」的单次现场**。8400/8410/9400 均无常驻服务，`d12-blindtest.md` 的 6/6 与 MTTD 数据是当时那次现场的行为，不是常驻服务的行为；复现需按各 README 自行拉起环境
3. **红队清单只覆盖已知失败模式，不穷举未知模式**。「盲测 6/6 全过」不证明第 7 场过，「红队通过」不证明换一个注入手法还能过
4. **测试绿不证明真实进程行为**。`@ConditionalOnMissingBean` 装配坑已证明单测/集成测试全绿而主路径起不来是可能的（README 踩坑记录），真实进程冒烟不可省
