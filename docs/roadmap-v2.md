# 迭代方向 V2 —— 模型越强越值钱的三样东西（含下一步计划）

> 状态：规划中（2026-10-31 起生效，每周日复盘滚动修订）
> 前置讨论：模型能力再上台阶时，本作品集哪些部分作废、哪些升值。结论沉淀于此。

## 0. 一句话换锚

- **V1 赌的是**："别人演示 AI 能做什么，我证明 AI 在生产里怎么不出事、怎么算得清账。"——隐含前提是模型还不行，我来补课。
- **V2 赌的是**：模型每强一代，补课的部分作废一批（故意的，补课本该廉价可弃）；但有三样东西**永远无法被模型内化**，且 AI 越行越值钱：**授权边界、成本账本、外部验证**。
- 原型不动，锚点换。三个原型的代码是存量资产，V2 的迭代全部发生在"围绕它们的边界与证明"上。

## 1. 为什么这三样无法内化

| 不可内化物 | 论证 | 对应资产 |
| --- | --- | --- |
| **授权边界** | 自我授权悖论：权限的划界者不能是被划界的对象。模型再完美，制度上审计独立性要求边界在模型外面，由人签字 | 原型 1 审批流 / 沙箱 / 白名单；原型 3 冻结清单 |
| **成本账本** | 模型不为自己的 token 付费。agentic 规模下一个任务几百次调用，成本从财务问题变成运行时安全问题（失控调用 = 运行时事故） | 原型 2 渠道四元组 / 熔断 / 账本 |
| **外部验证** | 自己证明自己不算证明。模型越可信，伪造"看起来可信的证据"的能力越强，独立核验与证据防伪越刚性 | verification/ 评分器 / 红队清单 / CI 门禁 |

失败的分布也在换：能力型失败（模型太笨）萎缩，判断型失败（做得到但不该做）、经济型失败（token 失控）变大。V1 的每个 artifact 逐个问一遍：它治理的是哪类失败？

## 2. 资产盘点：保值、换锚、故意作废

| 资产 | V1 卖点 | V2 卖点 | 判定 |
| --- | --- | --- | --- |
| 原型 1 审批流 / 沙箱 | 怕弱模型乱来（补课） | 约束强模型的授权边界（旋钮） | **换锚** |
| 原型 2 熔断降级 | 模型故障切换 | 供应链可用性（第三方中转不稳定是供应链问题，不随模型变强消失） | **保值** |
| 原型 2 成本账本 | 会记账 | 预算护栏（运行时安全） | **升值** |
| 原型 3 冻结检查清单 | 教 Agent 查什么 | 控制面的不变性（审计要的是"同一个审计"，不是更聪明的审计） | **升值** |
| verification/ 评分器 + 红队 | 自证清白 | 独立审计 + 证据防伪 | **升值最快** |
| 踩坑记录（代理劫持 / 端口占用 / H2 文件锁 / gitignore） | — | 环境层教训，不随权重升级 | **保值** |
| 手工诊断链编排、动作提取器 | 补课 | — | **故意作废**：能被下一代模型原生吸收，不为它优化 |
| 智能路由差异化（能力分表） | 省钱 | — | **高风险**：模型趋同即塌方，卖点必须迁到供应链 + 账本 |
| MTTD 竞速 | 硬指标 | — | **放弃叙事**：强模型会轻松达成，不再作为主枝 |

## 3. 三条主线（V2 迭代项，含 EverOS 借鉴）

EverOS（本地优先记忆运行时）通读后的结论：工程成熟度极高，最值得偷的不是代码是**四件套纪律**——数字必须可归因（run_spec.json）、失败必须分类（retryable/permanent）、声明不证明什么（fixture README 的诚实条款）、分层能力测试（tier1/2/3 + upgrade path）。下面逐条接进来。

### 主线 A：授权边界——从"门"到"标定过的旋钮"（原型 1）

- **A1 动作分类学**（借鉴 EverOS cascade 失败分类学：retryable / permanent，permanent 永不自动清除）
  给每个候选动作标注三元组：{可逆性（可逆/难逆/不可逆），影响面（单实例/跨实例/跨系统），爆炸半径（回滚成本）}。不可逆类无论模型多可靠，永不进自动白名单——这条线是制度线，不随模型能力移动；可逆类才参与"毕业"评估。
- **A2 信任标定实验**（V2 的招牌实验）
  同一审批流跑两代模型（现有数据：降级路径方舟代际 vs 主模型恢复后代际；GLM 接入后再加一代），量三个数：**误拦率（拦了多少本来该过的）、审批通过率、事故率**。回答"哪些动作类可以随模型变强毕业到自动执行"。市面上很少有人有这组数据，我们的靶场现成。
- **顺带关账**（known-defects 挂账项）：动作提取器兜底链路全自动跑通；MTTD 并行化收尾（只关账，不再当卖点）。
- **验收门**：动作分级表入库；≥2 个模型代际的误拦率数据可复核；实验记录可发布。

### 主线 B：成本账本——从记账到护栏（原型 2）

- **B1 渠道能力分层测试**（借鉴 EverOS integration 的 tier1/tier2/tier3 + `test_upgrade_path.py`）
  tier1 = 只剩 1 个渠道；tier2 = 主渠道 404/503 混合故障；tier3 = 全渠道健康 + 价目齐全。另加升级路径测试："先缺 GLM/DashScope，真 key 补上后不改动即通过"。渠道趋同风险被显式测出来，而不是等它塌。
- **B2 预算熔断**（对应 known-defects："LLM 侧配额/预算硬止损未做"）
  任务级 token / 美元预算，超限熔断并留痕。账本从"事后记账"升级为"运行时守门"——这是账本升值的直接落地。
- **B3 测量归因卡 run_spec**（借鉴 EverOS benchmarks 的 run_spec.json：每次运行记录实际模型、endpoint、包版本，保证数字可归因）
  三原型统一格式：{模型名，endpoint，key 指纹（非明文），配置版本，时间戳}。所有"数据有出处"的数字挂一张卡。没有它，换模型前后的数据不可比。
- **验收门**：tier 矩阵测试进 CI；预算熔断完成一次真实演练（超限→熔断→留痕→复盘）；usage-report.json 附 run_spec。

### 主线 C：外部验证——attestation 2.0（verification/）

- **C1 "我们的验证不证明什么"**（借鉴 EverOS 兼容基线 fixture README 的诚实条款：连手工合成的 fixture 都声明"这不证明什么"）
  known-defects.md 顶部新增一节，首批三条：precision/recall=1.0 只覆盖 drift 维度，不证明 credscan/exposure；e2e 数字来自现场单次跑，不是常驻服务；红队清单只列已知失败模式，不穷举。
- **C2 证据链防伪**（借鉴 EverOS "Markdown = 真相，索引可删可重建" 的存储分层：真相层与派生层分离）
  原始记录（approvals.jsonl、usage-report.json、真机报告）= 真相层；评分产物 = 派生层。验收标准定为重放：**删掉全部派生产物 → 从真相层重建 → 分数必须逐位复现**。再配哈希串联防篡改。强模型会写出漂亮的假报告，证据必须能被独立核验——CI 重放就是我们的锚。
- **C3 检查清单进化机制**（原型 3 联动）
  强模型负责提议"该查什么新的"（清单内容的进化），冻结清单负责"每次都查同一批"（执行的不变性）。流程：模型提议 → 人工评审 → 冻结进下一版清单，每次进化留记录。固化从"补课手段"变成"约束手段"。
- **验收门**：重放演练一次通过（同分）；known-defects 新节上线；至少一次有记录的清单进化。

## 5. 面试串场升级

现有串场保留，末尾追加定锚句：

> 模型每强一代，我这套东西里"替模型补课"的部分就作废一批——这是我故意的，补课的部分本来就该廉价可弃。但授权边界、成本账本、外部验证这三样恰好相反：AI 越行越值钱，因为它们永远无法被模型内化。我赌的不是"AI 现在还不行"，而是"AI 越行，生产环境越需要这三样"。

被追问"你的路由不就白做了吗"时的标准答案：路由代码贬值了，但做路由过程中被逼出来的定义（渠道四元组）、失败语义（瞬态/确定性错误分治）、账本纪律（未知价目记 null）全都是供应链与经济学层的，不贬值。资产会旧，被资产教出来的判断不会。
